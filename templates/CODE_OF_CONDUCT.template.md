`<repo-name>` is a small, `<solo-maintained / small-team>` project. This document is short on
purpose: it covers the basics of how people are expected to interact here, not a formal
governance process.

## Expected behavior

| Do | Don't |
|----|-------|
| Disagree with the idea, not the person | Insult, mock, or personally attack |
| Give feedback that's actionable | Give feedback that's just critical |
| Accept that maintainer time is limited; a slow or "not now" response isn't personal | Harass or pressure for faster responses |
| Ask before sharing someone else's information | Publish someone's private information without consent |

## Scope

Applies anywhere interaction happens around this project: GitHub issues, pull requests, code
review comments, and discussions.

## Reporting

GitHub has no general private-messaging feature between users, and a comment on an issue or PR is
public, so use a channel that's actually private:

- **Preferred**: open a [private security advisory](https://github.com/<owner>/<repo>/security/advisories/new).
  It's not just for vulnerabilities, it's the one channel on this repo that reaches
  **@<maintainer-handle>** directly and stays visible only to the two of you, which is what
  matters for a conduct report, especially one about another participant.
- For anything that needs GitHub's own moderation (not just this project's), use GitHub's
  [Report abuse](https://github.com/contact/report-abuse) form. That goes to GitHub Trust &
  Safety, not the maintainer, so use it alongside a report here, not instead of one.

## Enforcement

There's no committee here. The maintainer decides case by case, and depending on severity that can
mean asking someone to rephrase, removing a comment, or blocking further interaction (issue/PR
lock, GitHub block) for repeated or serious violations.
